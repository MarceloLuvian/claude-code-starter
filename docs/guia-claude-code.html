CLAUDE CODE · STARTER

Guía: cómo usar este proyecto con Claude Code

De cero a tu primer proyecto: instalar, iniciar sesión con tu cuenta, y usar la estructura .claude/ y su equipo de agentes.

1. Qué es esto

Un starter que ya trae la estructura .claude/ lista: el manual del proyecto (CLAUDE.md), permisos y hooks (settings.json), y un equipo de agentes (arquitecto, planner, backend, frontend, QA, PM, revisor de código y analista de marketing). Lo clonas, lo abres con Claude Code y empiezas.

Necesitas: una cuenta de Claude, git, y Node 18+ (para instalar Claude Code).

2. Instalar Claude Code

npm install -g @anthropic-ai/claude-code

Verifica con claude --version. (En macOS/Linux/Windows funciona igual; usa también el instalador oficial si prefieres.)

3. Iniciar sesión con tu cuenta

Claude Code se usa con tu propia cuenta. La primera vez que lo abras, te pedirá iniciar sesión:

Paso 1. En una terminal, escribe claude y presiona Enter.
Paso 2. Te mostrará un enlace / abrirá el navegador. Inicia sesión con tu cuenta de Claude (la misma de claude.ai) o con tu API key, según el método que uses.
Paso 3. Autoriza el acceso. Vuelve a la terminal: ya quedaste conectado (la sesión se guarda, no tienes que repetirlo cada vez).
Tu sesión es personal. No compartas tu cuenta ni tus credenciales. Si trabajas en equipo, cada quien inicia sesión con la suya.

4. Traer el starter a tu máquina

git clone <URL-del-repo> mi-proyecto
cd mi-proyecto

O copia solo la carpeta .claude/ y el archivo CLAUDE.md dentro de un proyecto que ya tengas.

5. Abrir el proyecto

cd mi-proyecto
claude

Claude lee primero tu CLAUDE.md y carga lo que hay en .claude/. Ya tienes agentes, el comando /commit y la skill disponibles.

6. Qué hace cada pieza

PiezaPara qué
CLAUDE.mdReglas, estilo y decisiones del proyecto. Edítalo con lo tuyo: sin esto, el agente adivina.
.claude/settings.jsonPermisos (qué puede correr sin preguntar / qué se niega) y registro de hooks.
.claude/agents/El equipo de sub-agentes (cada uno aislado, con sus tools).
.claude/commands/Atajos /comando — aquí viene /commit.
.claude/skills/Capacidades reutilizables (ej. resumir un PR).
.claude/hooks/Scripts que corren solos en eventos (ej. formatear tras editar).
.claude/plugins/Empaqueta agents + commands + hooks para compartir.

7. El equipo de agentes

Invoca un agente pidiéndolo por su nombre. Son genéricos: sirven para desarrollo y marketing.

AgenteÚsalo para
architectDiseñar arquitectura: stack, módulos, carpetas, patrones.
plannerRequerimientos → historias de usuario + backlog priorizado.
dev-backendLógica, servicios, APIs, datos, auth, jobs.
dev-frontendUI, componentes, estilos, formularios.
qa-engineerPlan de pruebas y tests (incl. seguridad).
pm-statusReporte de estado verificado vs. código y git.
code-reviewerRevisar el diff actual y cazar bugs.
marketing-analystAuditar una web/landing (mensaje, CTA, UX, SEO).

8. Prompts para arrancar

Iniciar un proyecto web nuevo

Quiero arrancar un proyecto web nuevo. Sigue el flujo del equipo:
1. Con el agente "planner": pregúntame lo necesario y genera las historias + backlog.
2. Con "architect": propón stack y arquitectura en docs/architecture.md. Espera mi OK.
3. Con "dev-backend" y "dev-frontend": implementa la primera historia (vertical slice).
4. Con "qa-engineer": tests de esa historia.
No hagas push. Pregunta antes de decisiones grandes.

Analizar una web con marketing

Usa el agente "marketing-analyst" para auditar https://ejemplo.com
Dame hallazgos priorizados (alto/medio/bajo) de mensaje, CTA, UX, copy, prueba social
y SEO, y los 3 cambios de mayor impacto. Solo análisis, no cambies nada.

9. Tips

  • Lo primero: edita CLAUDE.md con el stack y las reglas reales de tu proyecto.
  • Ajusta los permisos de settings.json y el formateador en hooks/format.sh a tu stack.
  • Usa /commit para commits limpios; el agente code-reviewer antes de mergear.
  • Todo es texto plano y versionable: tu configuración de Claude viaja con el repo.
